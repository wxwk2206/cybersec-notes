挖洞的完整流程，核心思想只有一句：**不是拿扫描器喷一遍，而是理解这个系统是给谁用、钱和权限落在哪，然后找开发者没想到的地方**。下面按纯手工的真实顺序讲，从打开电脑到交报告。

---
## 第 0 步：定范围(5 分钟)
前提是你有授权——SRC 平台、众测项目、或客户给的测试范围。然后判断你要挖的是哪种：
- **固定清单**(用户给了 URL/域名列表)→ 就挖这些，不偷偷扩到别的
- **只给一个集团名** → 自己圈面：业务名、产品线、全资子公司、备案根域，全部列成种子清单落盘
这一步的关键：**种子要多**。一个集团可能有几十上百个域名，只盯着官网那一个，基本挖不出东西。

## 第 1 步：资产收集 + 清洗(侦察)
**搜**：拿种子去 FOFA / Hunter / Quake,配合 subfinder、crt.sh 证书透明度捞子域。
**洗**(这步偷懒后面全是白费劲)：

| 处理 | 标准 |
|------|------|
| 去重 | 同一 host:port 只留一条 |
| 去废 | CDN、图床、纯静态页、停放页、无解析的 |
| 去非存活 | 超时、探不通。**注意 401/403/登录墙算活的**，后面有面 |
| 归属 | 只挖 100% 控股的子公司资产，参股公司的洞不算这个 SRC 的，白挖 |

洗完剩下的才是真正要打的清单。

## 第 2 步：挑入口进站
起手优先打：业务 JSON 接口、管理后台、Swagger、Actuator、调试口——这些是肥面。
**打开是登录页怎么办？** 这是最常见的坑。登录页 ≠ 空资产，先找业务面：
- 看 URL 里的 `service=` / `redirect_uri=` / `returnUrl=` 跳到哪
- 看页面 JS 里的 `baseURL` / `apiHost` / `/prod-api`
- 看 302 的 Location 头
- 同品牌的 `api.` / `admin.` / `gateway.` 子域
业务面找到了就挖那边的**未登录接口**。登录表单本身:空密码、跳步、改响应包试一下，打通或证伪就停——不要在验证码和弱口令字典上耗一下午。

这些口不是碰运气碰到的，来源就三条通道：**① 页面/JS 自己露出来的，② 按技术栈猜路径试出来的，③ 测绘和扫描搜出来的**。
### 通道一：JS 和抓包——业务 JSON 接口的主来源

业务接口绝大多数是前端 JS 调的，所以 JS 就是接口目录：
1. **F12 → Network → 筛 Fetch/XHR**,把页面每个功能点一遍(搜索、筛选、翻页、提交、导出)，让请求自己飞出来。这是最正宗的来源，参数都是真实的。
2. **全量拉 JS 分析**：F12 → Sources 把 JS 都存下来，然后搜这些关键词——`/api/`、`baseURL`、`apiHost`、`/prod-api`、`/gateway/`、`fetch(`、`axios`。工具可以用 JSFinder/LinkFinder 自动提取，手工 grep 也行。
3. **顺带翻到的钥匙**：路由表里 hidden/admin 的页面、sourcemap(`.js.map` 下载下来能还原完整前端源码)、JS 里写死的演示号/测试租户、`env.js`/`config.js` 里的内部 host。
4. **前端没了或接口藏在登录墙后**：上 APP 抓包(绕过证书校验用 objection/Frida)、反编译小程序(wxapkg 解包)，里面 baseURL 和全部 API 都在明文里。

### 通道二：按技术栈对路径——Swagger/Actuator/调试口的来源

先认栈(Wappalyzer,或者看响应特征：错误页样式、`Set-Cookie` 名字——`JSESSIONID`=Java、`PHPSESSID`=PHP),认准了再对路径，命中率完全不同：

| 看到什么 | 去试这些 |
|----------|----------|
| **Spring Boot**(白标错误页、`X-Application-Context`) | `/actuator`、`/actuator/env`、`/actuator/heapdump`、`/actuator/mappings`;老版本不带前缀： `/env`、`/heapdump`。heapdump 拉下来 MAT/JXray 分析，内存里全是数据库密码和 AKSK |
| **Java + Swagger** | `/swagger-ui.html`、`/v2/api-docs`、`/v3/api-docs`、`/doc.html`(knife4j)、`/swagger-resources`。微服务架构下每个服务一份:`/用户服务名/v2/api-docs`,服务名从注册中心(`/eureka/apps`)或 mappings 里抄 |
| **Druid** | `/druid/index.html`——默认 `admin/admin` 或干脆没鉴权，session 监控页直接看别人的 Cookie |
| **Nacos** | `/nacos`,默认 `nacos/nacos`,配置中心里是全公司数据库连接串 |
| **Tomcat / 中间件** | `/manager/html`(tomcat 默认口)、`/console`(WebLogic)、`/jmx-console`(JBoss) |
| **PHP** | `/_profiler`、`/_telescope`(Laravel 调试)、`/phpinfo.php`、`/phpmyadmin/` |
| **通用敏感文件** | `/.env`、`/.git/config`、`/WEB-INF/web.xml`、`/backup.zip`、`/swagger.json` |

**注意端口**：管理端口经常和业务端口分离。80/443 上没有，不代表 9090/9001/8001 上没有——所以前面要配端口扫描(masscan/nmap 全端口)，对每个开着的端口都过一遍上面的路径表。

**管理后台**：子域枚举时专门留意 `admin.` / `manage.` / `console.` / `ops.` / `boss.` 前缀；目录字典打 `admin`、`manage`、`console`、`dashboard`、`system`;另外别忘了通道一——前端路由表里经常藏着不显示的管理页面路由。

### 通道三：测绘 + 扫描——把范围里的这类口主动捞出来
进站前用测绘语法把整个范围里的肥面先捞一遍(FOFA 示例)：
```
domain="target.com" && body="swagger"          # 全域找 swagger
domain="target.com" && title="管理"             # 找后台
domain="target.com" && body="Whitelabel Error Page"   # 找 Spring Boot 站
domain="target.com" && header="actuator"
cert="target.com"                              # 证书关联,捞出隐藏子域
```
进站后目录爆破收尾：ffuf/dirsearch 带按栈定制的字典(Spring 站用 actuator/swagger 字典，别拿 PHP 字典喷 Java 站)。
### 进站固定动作清单(合到一起)
站在一个新站面前，按顺序做：
1. **看指纹**：响应头、Cookie 名、错误页 → 认出栈和框架
2. **打开功能页**：F12 Network 筛 XHR,点一遍功能 → 真实接口和参数到手
3. **拉 JS**:grep `api/`、`baseURL`、盐、演示号、hidden 路由
4. **对路径表**：按第 2 步认出的栈，把对应的那一行路径全试一遍(`/actuator`、`/swagger-ui.html`、`/druid`、`/.env`……)
5. **全端口扫**：管理口十有八九藏在非 80 端口上，扫完对每个端口再过一遍路径表
6. **回包留神**：任何响应里冒出的内部 host、服务名、路径，回头都对一遍路径表

这套动作熟练后一个站 10~15 分钟，肥面基本跑不掉。这和上面教的“说清这摊 → 建清单 → 打矩阵”是衔接的：1~6 步就是建清单的过程，清单里的口再按价值排序往里打。
## 第 3 步：说清这摊(理解业务，3~5 行)

进站先不动手，写清楚四件事：
1. **谁在用**——C 端用户、商家、还是内部运营？
2. **核心对象是什么**——订单、工单、优惠券、文档？
3. **钱、权、状态落在哪几个字段**——`amount`、`role`、`status`?
4. **没登录能碰到哪一层**?

说不清就回去抓包补。后面所有测试都围着这几样动。很多洞的来源就是：开发者假设“这个接口只有商家自己能调”，而你发现 C 端会话也能调。

## 第 4 步：建接口清单(抽 JS + 抓包)
有前端就全量拉 JS,提取 `api/` 路径建清单。**但 JS 不只抽 path**,这几样是钥匙：

| 抽到什么 | 用法 |
|----------|------|
| 签名盐、硬编码密钥 | 自己算签名，打“只要 sign 不要 Cookie”的口 |
| 密文 id + 前端公钥 | 自己加密一个别人的 id 再传 |
| hidden/admin 路由、异步 chunk | 页面不展示也直接打对应 API |
| **写死的演示号、测试租户** | 直接当账号用，这是金钥匙 |

同时开 Burp 抓真实请求，把 query + body 的**全部参数**列成表——包括看着不起眼的短枚举字段(`vote`、`status`)。**回包里冒出来的 id、下载地址、token、内部 host,随手进清单**，列表接口过了，附件/导出还要再打一枪(父对象过了鉴权，子对象经常没过)。

## 第 5 步：按价值排序打(力气分配)

不是挨个漏洞类型平均用力。**越容易出高危的越先打**：
1. **未登录出他人数据**——不带 Cookie 打关键接口，通了立刻换 id 看能不能出别人的
2. **认证接管**——发验证码、重置密码、改绑手机/邮箱这几个口：回包里有没有码？码绑不绑号？最后一步把 uid 换成别人的行不行？
3. **换 id(不限字段名)**——这是手工挖洞的**最高频产出**。有会话的话走对象图：列表 → 详情 → 附件/导出，**每一层都换 id**:邻号、`0`/`-1`/空、从回包里抄来的别人的 id
4. **有号的写/逻辑**——写接口加 `role`/`isAdmin` 字段、改金额/状态、多步流程跳步、领券并发
5. **注入/SSRF/XSS/RCE**(四件套)——打在上面那些**已经出业务数据的参数**上

## 第 6 步：四件套怎么打(有差分面才打)

四件套 = 注入、SSRF、XSS、RCE。**不是每个 path 喷一个单引号**，要打在“能看出反应”的参数上，按栈选探针：

- **注入**：JSON 接口打 Mongo 操作符(`{"$ne": ""}`);搜索框打 OR+total;Java 栈打 HQL/SpEL;有模板渲染打 SSTI;SQL 面走 `'`/布尔/延时。**差分是硬证据**：基线 `total=2`,payload 后 `total=数千万` → 跨租户元数据，真洞
- **SSRF**:所有 URL/回调/webhook/preview/file 类参数，打内网地址、云元数据(`169.254.169.254`)、自己的外带监听
- **XSS**:反射点看参数回显处打标签；存储点找昵称/备注/文件名，写进去再读回
- **RCE**:看到命令执行、模板、表达式、文件转换、反序列化入口，跟到能不能执行或证伪

被 WAF 拦了：换编码(`%0a`、双写、大小写)、**换位置**(query 换 json、换 header、换 path)。

## 第 7 步：挖到苗头不停半截(升链)

这是新手最容易吃亏的地方——拿到中危就交，其实差一步就是高危：

- 文件上传通了 → 别停在“能传能下”，找可执行路径、找 SSRF 链
- 发码接口通了 → 跟整条认证链
- 能读一个别人的对象 → 换遍所有 id 看圈多大
- 中危同一对象，先升到“能写 / 跨用户 / 接管 / 能执行”再换站

## 第 8 步：验证 + 写报告

宁可漏报不误报。每个点交之前自问：输入可控吗？过滤绕过了吗？前置条件是什么？最坏影响是什么？复现步骤别人照着能不能跑通？报告写：标题、URL、复现步骤(带请求/响应包)、危害、修复建议。证据链完整，审核一次过。

## 第 9 步：换站，循环

本站矩阵勾完(或确认打不动)→ 清单里下一条活面 → 本种子全部挖完 → 换下一个种子。**报告写完不收工**，一直循环到把队列清完。

---

## 贯穿全程的五个心法

1. **找认知盲区，不是找漏洞模式**——每打一个站，问自己“开发者在这里假设了什么？这个假设什么时候会破？”比如“前端加密了 id,后端就不再鉴权了”——这本身就是个假设，破它。
2. **差分思维**——一切结论靠对照：正常请求 vs 探针请求，条数、字段、耗时、回包结构的变化才是证据。“感觉有洞”不算。
3. **回包当线索**——所有响应里出现的 id/URL/token/host 都是下一条测试的输入，当垃圾丢掉等于白挖。
4. **肥面深挖、瘦壳一眼**——JS 多、业务接口多、有后台的站值得砸时间；403 空壳、同构镜像一眼证伪就跳，别把一天耗在 15 个长得一样的登录页上。
5. **不偏科**——只堆未授权读是新手通病。注入/SSRF/XSS/RCE 每站都要真发过 payload 或写明为什么没有入口，偏科会让你错过藏在业务参数里最肥的洞。

一句话总结：**圈面 → 清洗 → 找业务面 → 建清单 → 换 id 和认证口先打 → 四件套打在出数据的参数上 → 中危升链 → 报告 → 换站循环**。想拿一个真实目标练的话，给我一个 SRC 平台名或集团名，我带你按这套流程走一遍。
