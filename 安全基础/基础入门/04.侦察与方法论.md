
> [!abstract] 核心观点
> 多数高危漏洞来自**系统化覆盖**，而不是巧妙的 payload。
> 侦察的产出不是「扫到了什么」，而是「一份完整、可复用的攻击面清单」。

> [!warning] 使用前提
> 以下技术仅限**授权目标 / 合法研究 / 防御验证 / 漏洞赏金规则**范围内使用。未获授权的扫描与利用均属违法。

---

## 1. 侦察层级（总纲）

整个流程是一条自上而下的链条，后面所有内容都是往这条链里填材料：

```text
⭐ 目标选择
   └── 范围定义（范围内资产）
        └── 资产发现（子域、IP、域名）
             └── 技术指纹（在跑什么）
                  └── 端点发现（攻击面）
                       └── 漏洞测试（逐漏洞类型）
```

一句话：==先测绘，再找洞==。没有清单，就没有覆盖。

> [!important] 关键结论
> 上来就对着一个 URL 打 payload，是效率最低的做法。真正的差距不在 payload 有多花哨，而在**你看见了多少别人没看见的入口**。

## 2. 三阶段执行流程

| 阶段 | 目标 | 产出 |
| --- | --- | --- |
| **① 测绘** | 把目标彻底看一遍 | 资产清单 + 技术栈 + 端点/参数列表 |
| **② 路由** | 按现象决定打哪儿 | 按命中概率排序的测试方向 |
| **③ 深挖** | 逐点验证并放大影响 | 可复现的 PoC |

### 2.1 阶段一：测绘（Recon）
1. **定范围** —— 确认授权范围内的资产，绝不越界
2. **子域枚举** —— 被动优先，主动补充（详见 [[03.信息收集]]）
3. **端口与服务** —— 重点找非标准端口上的管理面
4. **技术指纹** —— 确定中间件 / 框架 / 版本
5. **端点与参数** —— 目录爆破 + JS 挖接口 + 隐藏参数发现
6. **顺手捡配置错误** —— `.git` / `.env` / 备份文件 / 默认口令

### 2.2 阶段二 → 三：走向
- 拿到现象后，用第 14 节的「现象 → 漏洞类别路由表」决定测试方向
- 再按第 8 节的「靶标分诊」排优先级
- 最后用第 7 节的 ZSEANO 六步法逐点深挖

## 3. 子域枚举（关键第一步）

> [!tip] 本节只列方法论要点
> 具体工具操作（ksubdomain / puredns / OneForAll / 字典准备）已整理在 [[03.信息收集]]，此处不重复。

### 3.1 两种策略

| 策略 | 特点 | 风险 |
| --- | --- | --- |
| **被动枚举** | 不向目标发 DNS 查询，从第三方数据源捞 | 无感知、无风险 |
| **主动枚举** | 直接对目标 DNS 爆破、解析 | 可能触发告警/封禁 |

### 3.2 核心命令
```bash
# ⭐ 被动：聚合多来源收集
subfinder -d target.com -o subdomains.txt
amass enum -passive -d target.com

# ⭐ 被动：证书透明日志（免费、量大）
curl -s "https://crt.sh/?q=%.target.com&output=json" | jq -r '.[].name_value' | sort -u

# 主动：Massdns + 字典批量爆破
massdns -r /path/to/resolvers.txt -t A -o S -w output.txt \
  <(cat wordlist.txt | sed 's/$/.target.com/')

# ⭐ 批量解析，把活的和死的分离
cat subdomains.txt | dnsx -a -resp -o resolved.txt

# 推荐字典：SecLists/Discovery/DNS/
```

### 3.3 虚拟主机发现（同名不同站）

同一个 IP 上挂着多个站点，靠 `Host` 头区分——**常规子域枚举发现不了**：
```bash
# ⭐ ffuf vhost 模式：改 Host 头，看响应是否变化
ffuf -w wordlist.txt -u https://target.com \
  -H "Host: FUZZ.target.com" -mc 200,301,403

gobuster vhost -u https://target.com -w wordlist.txt
```

## 4. 服务与端口发现
```bash
# 快速扫常见端口
nmap -T4 -F target.com -oN ports.txt

# 对已解析的 IP 段全面扫描（注意只填授权范围内的端口）
cat resolved_ips.txt | nmap -iL - --open -p 80,443,8080,8443,8888,3000,5000 -oG scan.txt

# ⭐ httpx 做 HTTP 探活，顺手拿标题和技术栈
cat subdomains.txt | httpx -title -tech-detect -status-code -o live_hosts.txt

# 大 IP 段提速（masscan 速度极快，但极易触发告警）
masscan -p 80,443,8080,8443 10.0.0.0/8 --rate=1000
```

> [!warning] 注意
> `masscan` 发包速率极高，在真实授权项目中**必须先和对方确认速率上限**，否则容易被判为 DoS。

## 5. WEB 技术指纹

```bash
# 自动化识别
whatweb https://target.com
httpx -u https://target.com -tech-detect

# ⭐ 手工查响应头（最快、最准）
curl -sI https://target.com | grep -i "server\|x-powered-by\|x-generator\|cf-ray"
```

### 指纹识别来源

| 来源 | 示例 | 推断 |
| --- | --- | --- |
| `Server` 头 | `nginx/1.18`、`Apache/2.4`、`IIS/10.0` | 中间件类型与版本 |
| `X-Powered-By` | `PHP/7.4`、`ASP.NET` | 后端语言 |
| **Cookie 名** | `PHPSESSID` / `JSESSIONID` / `_rails_session` | PHP / Java / Rails |
| HTML 注释 | `<!-- Drupal 9 -->` | CMS 类型 |
| Meta generator | `<meta name="generator" content="WordPress 6.2">` | CMS 与版本 |
| JS 框架文件 | `/static/js/angular.min.js` | 前端框架 |

> [!tip] 技巧
> Cookie 名是**最容易被忽略的指纹**。很多人只看 `Server` 头，但 `Server` 常被反代改写；Cookie 名是后端语言自己起的，基本改不掉。

## 6. 端点发现

### 6.1 目录爆破

```bash
# ⭐ ffuf（最快）
ffuf -u https://target.com/FUZZ \
  -w /usr/share/seclists/Discovery/Web-Content/raft-medium-files.txt \
  -mc 200,301,302,403 -t 50 -o dirs.txt

# Gobuster（带扩展名）
gobuster dir -u https://target.com -w wordlist.txt -x php,html,js,json

# feroxbuster（递归，适合深层目录）
feroxbuster -u https://target.com -w wordlist.txt -x php,html,txt -r
```

### 6.2 参数发现（隐藏参数）

```bash
# ⭐ Arjun：自动探测未在页面出现的隐藏参数
arjun -u https://target.com/api/endpoint

# x8：另一款隐藏参数发现器
x8 -u https://target.com/api/endpoint -w params-wordlist.txt
```

### 6.3 JavaScript 源码挖掘

**前端 JS 里藏着后端接口**，这是现代应用最关键的攻击面来源：

```bash
# ⭐ 从 JS 文件里正则抠出所有路径
gau target.com | grep '\.js$' | httpx -mc 200 | xargs -I{} curl -s {} | \
  grep -oE '"/[a-zA-Z0-9/_-]+"' | sort -u

# LinkFinder：专门提取 JS 中的端点
python3 linkfinder.py -i https://target.com -d -o output.html

# 历史 URL 收集
gau target.com | sort -u > all_urls.txt
waybackurls target.com | sort -u > wayback_urls.txt
```

### 6.4 API 端点发现

```bash
ffuf -u https://target.com/FUZZ \
  -w /SecLists/Discovery/Web-Content/api/api-endpoints.txt

# Swagger / OpenAPI 常见路径：
# /swagger.json   /api-docs   /openapi.json   /v2/api-docs   /.well-known/   /docs/

# GraphQL 常见路径：
# /graphql   /gql   /v1/graphql   /api/graphql
```

## 8. ZSEANO 测试方法论

### 8.1 四条核心理念

1. **在一个项目上深挖**，而非撒网很多个 —— 彻底吃透应用
2. **建立公司画像** —— 技术栈、开发者、流程
3. **看别人不看的地方** —— 错误页、管理路径、旧版本、移动端 API
4. ⭐ **跟着过滤器走** —— 若某处过滤了输入，说明该功能存在，且可能被绕过

> [!important] 关键结论
> 开发者不会为**不存在的功能**写过滤逻辑。看到过滤，就等于看到了「这里有个处理点」的路标。

### 8.2 单点六步测试顺序

```text
1. 无害 HTML 标签（<h2>、<img>）→ 是否回显？
2. 不完整标签 → 会怎样？（<iframe src=//evil.com ）
3. 编码测试 → %0d、%0a、%09、<%00
4. ⭐ 也要观察输出（不只看响应码）—— 你的输入出现在哪里？
5. 在所有结构相似页面测同样输入（共享代码 → 共享漏洞）
6. 查移动端 / API 端点是否存在同样参数（那边防护通常更弱）
```

### 8.3 参数洞察（每个参数都在讲故事）

| 参数形态 | 服务端行为 | 对应漏洞 |
| --- | --- | --- |
| 文件名 | OS 交互 | 路径穿越 / CMDi |
| URL / 位置 | HTTP 抓取 | SSRF |
| 模板 / HTML | 渲染函数 | SSTI |
| XML 字段 | 解析器 | XXE |
| SQL 过滤 | 查询 | SQLi |
| 用户内容 | 存储 | 存储型 XSS |

## 9. 靶标分诊（时间花在哪）

### 9.1 目标筛选

| 选择 | 理由 |
| --- | --- |
| ✅ 范围大的项目（`*.target.com`） | 攻击面大 |
| ✅ 为 P2/P3 也付钱的项目 | 不用死磕 RCE |
| ✅ 近期技术变更的项目 | ==迁移 = 新漏洞== |
| ✅ 活跃开发的项目 | 新功能 = 新攻击面 |
| ❌ 冻结 / 老旧的代码库 | 知名 CVE 早被领完 |
| ❌ 范围狭窄的严格项目 | 攻击面太小 |

### 9.2 功能优先级（按出洞概率）

```text
优先级 1：认证、密码重置、2FA      → 账户接管
优先级 2：文件上传、资料编辑、API  → 存储型 XSS、IDOR
优先级 3：管理面板、用户管理       → BFLA、提权
优先级 4：支付流程、订阅           → 业务逻辑
优先级 5：导入 / 导出、模板渲染    → XXE、SSTI
```

## 12. Java 中间件指纹矩阵

| 中间件 | 检测路径 | 关键指标 |
| --- | --- | --- |
| **Apache Tomcat** | `/manager/html`、`/manager/status` | 默认凭据 `tomcat:tomcat`、`admin:admin` |
| **JBoss / WildFly** | `/jmx-console/`、`/web-console/` | JMX MBean 访问、WAR 部署 |
| **WebLogic** | `/console/`、`/wls-wsat/` | 7001/7002 上的 T3 协议、IIOP |
| **Spring Boot Actuator** | `/actuator/`、`/actuator/env`、`/actuator/heapdump` | JSON 端点列举、堆 dump 含密钥 |
| **Spring Boot（替代路径）** | `/actuator/jolokia`、`/actuator/gateway/routes` | Jolokia JMX 桥、Gateway 路由注入 |
| **Jenkins** | `/script`、`/manage` | Groovy 控制台、cookie 中的 API token |
| **GlassFish** | `/common/`、`/theme/` | 4848 管理端、默认空密码 |
| **Jetty** | `/jolokia/` | JMX 访问 |
| **Resin** | `/resin-admin/` | 管理面板 |

### 12.1 Spring Boot Actuator 利用优先级

```text
/actuator/env            → 泄露环境变量（数据库凭据、API 密钥）
/actuator/heapdump       → 下载 JVM 堆 → 在内存中搜密码
/actuator/jolokia        → JMX → 经 MBean 操纵可能 RCE
/actuator/gateway/routes → Spring Cloud Gateway → SpEL 注入（CVE-2022-22947）
/actuator/configprops    → 所有配置属性
/actuator/mappings       → 所有 URL 映射（隐藏端点）
/actuator/beans          → 所有 Spring bean
/actuator/threaddump     → 线程 dump（栈帧中可能泄露会话 token / 密钥）
```

> [!tip] 技巧
> `/actuator/heapdump` 下载下来后用 `grep` 或 MAT 搜 `password`、`secret`、`token`，命中率很高——**内存里的明文密码**是最容易被忽略的一类泄露。

## 14. 附：现象 → 漏洞类别路由表

> 侦察完成后，用这张表决定「先打哪条线」。表出自 HackSkills 主入口 `hack`，是本文档的自然下一步。

| 观察到的现象 | 优先测试方向 |
| --- | --- |
| 输入回显到 HTML / JS | XSS / SSTI |
| 服务器主动 fetch URL / 主机名 | SSRF |
| 接受 XML / Office / SVG | XXE |
| 路径、文件名或下载端点可控 | 路径穿越 / LFI |
| API 中出现大量对象 ID | IDOR / BOLA / BFLA |
| 登录、重置密码、2FA、会话 | 认证绕过 / JWT / OAuth |
| 多步交易、优惠券、定价、库存 | 业务逻辑 |
| 暴露 MongoDB / JSON 查询语法 | NoSQL 注入 |
| CLI 工具、图像处理、导入器 | 命令注入 |
| HTTP 解析异常 / 前后端分帧不一致 | 请求走私 |
| Node.js JSON 处理 / 可控 `__proto__` | 原型链污染 |
| PHP 弱比较 / 0e 哈希 | 类型混淆 |
| 重复参数名 / WAF 与应用解析不一致 | HTTP 参数污染 |
| 一次性操作（优惠券 / 库存 / 重置） | 竞态条件 |
| 可访问 `.git` / `.svn` / `.env` 路径 | 源码泄露 |
| CSV / Excel 导出功能 | CSV 公式注入 |
| WebSocket 协议升级 | WebSocket 安全 |
| 内部包名 / 供应链清单 | 依赖混淆 |

## 15. 高价值专家直觉

> [!important] 八条经验
> 1. **同一套过滤逻辑常在多个页面复用** —— 一个点能绕过，相似页面通常也能
> 2. **参数名本身也是攻击面** —— WAF 常只检查值，不检查名
> 3. **二次漏洞很常见** —— 存储时安全 ≠ 之后读入危险上下文时也安全
> 4. **BOLA 本质是「已认证但未授权」** —— A/B 账号切换重放是唯一可靠验证手段
> 5. **旧版 API 最可能漏补丁** —— 修了 v2 不代表 v1 已下线
> 6. **业务逻辑漏洞往往影响最大** —— 扫描器发现不了，存活时间也更长
> 7. **竞态条件优先打一次性动作** —— 优惠券兑换、领取、重置、邀请、试用、库存扣减
> 8. **JWT 攻击先核实上下文** —— 先看 `alg`、`kid`、JWKS 和密钥来源，不要盲目撒 payload
