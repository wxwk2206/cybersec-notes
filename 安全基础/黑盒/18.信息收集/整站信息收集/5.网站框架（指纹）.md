识别网站使用的**后端Web框架**（如 Laravel、Django、Spring Boot、Express、Flask、Rails 等）是渗透测试信息收集的重要一环。下面从**最简单到最深入**，给你一套可操作的方法。
## 一、浏览器开发者工具 + 插件（零门槛）
### 1. Wappalyzer 插件
+ 安装 Chrome/Firefox 插件 **Wappalyzer**。
+ 访问目标网站，点击图标 → 直接列出检测到的框架、库、服务器等信息。
+ **优点**：非入侵，识别准确率较高（尤其对常见框架）。
+ **局限**：依赖规则库，对深度定制或混淆的网站可能误判。
### 2. BuiltWith 在线工具
+ 访问 `https://builtwith.com`，输入域名。
+ 查看 “Web Framework” 分类。
+ **优点**：不需要安装插件，适合批量查询。

## 二、查看 HTTP 响应头（手工 + curl）
不同框架会在响应头中留下特征，尤其 `X-Powered-By`、`Set-Cookie`、`Server` 等。

| 框架 | 特征响应头 / Cookie | 示例 |
| --- | --- | --- |
| **Laravel (PHP)** | `Set-Cookie: laravel_session=...` | laravel_session |
| **Django (Python)** | `Set-Cookie: sessionid=...`   `X-Frame-Options: DENY`（常见） | sessionid |
| **Spring Boot (Java)** | `X-Application-Context`   `Set-Cookie: JSESSIONID=...` | JSESSIONID |
| **Express (Node.js)** | `X-Powered-By: Express`（默认） | Express |
| **Ruby on Rails** | `Set-Cookie: _session_id`   `X-Powered-By: Phusion Passenger` | _session_id |
| **Flask (Python)** | `Set-Cookie: session=...`（值经过签名，格式特殊） | session |
| **ASP.NET MVC** | `X-AspNetMvc-Version`, `X-AspNet-Version` | 数字版本号 |


**命令行快速检查**：
```bash
curl -I https://target.com
```
如果使用了反向代理或 CDN，这些头可能被剥离或修改，但依然值得查看。

## 三、静态文件路径与命名特征
框架通常会按照固定规则存放静态资源（CSS、JS、图片），通过查看 HTML 源码可以找到特征路径。

| 框架 | 静态文件路径特征 |
| --- | --- |
| **Laravel** | `/css/app.css` 或 `/js/app.js`（版本混编）   `/vendor/` 目录常见 |
| **Django** | `/static/admin/css/` 或 `/static/rest_framework/` |
| **Spring Boot** | 默认静态资源放在 `/static/`、`/public/`、`/resources/`，但无强特征；若启用 Swagger，则 `/swagger-ui.html` 或 `/v3/api-docs` |
| **Express + EJS** | `/public/stylesheets/` 等 |
| **Rails** | `/assets/application-xxxxxxxxx.css`（带指纹哈希） |

**小技巧**：查看 `favicon.ico` 或 `robots.txt` 有时能发现框架遗留的默认文件。

## 四、默认错误页面风格（主动触发）
访问一个不存在的路径 `/not-exist-123456`，观察 404/500 页面风格和输出内容。
+ **Laravel**：默认 Whoops 错误页面（橙色背景，详细堆栈，但生产环境可关闭）；如果开启了调试，会显示 `.env` 等相关信息。
+ **Django**：调试模式下蓝色背景，显示 `settings.py` 路径、数据库查询等。
+ **Spring Boot**：白标错误页（Whitelabel Error Page），JSON 格式的 `/error` 响应。
+ **Flask**：简单 HTML “Not Found” 或 调试模式下的 Werkzeug 报错（带代码片段）。
+ **Express**：纯文本 “Cannot GET /xxx”。

注意：生产环境通常关闭调试，但仍可能保留框架特征的 404 页面（如 Spring Boot 默认白标页）。

## 五、特定路径与 API 端点暴露
许多框架带有默认的辅助路径，若能访问则直接暴露身份。

| 框架 | 特征路径 |
| --- | --- |
| **Spring Boot Actuator** | `/actuator/info`, `/actuator/health`（可加前缀如 `/manage`） |
| **Django** | `/admin/`（默认后台，有特定样式） |
| **Laravel** | `/vendor/`（目录浏览可能开启，很危险） |
| **Flask / FastAPI** | `/docs`, `/redoc`, `/openapi.json`（如启用自动文档） |
| **Rails** | `/assets/` 路由模式 |

## 六、使用专业扫描工具
| 工具 | 特点 | 命令示例 |
| --- | --- | --- |
| **WhatWeb** | Kali 内置，指纹库丰富 | `whatweb https://target.com` |
| **Wappalyzer CLI** | 官方命令行版 | `wappalyzer https://target.com` |
| **Retire.js** | 主要识别前端库，但可间接提示框架 | `retirejs --scan` |
| **CMSeek** | 偏 CMS，但也支持部分框架 | `python3 cmseek.py -u target.com` |

## 七、综合判断流程（推荐）
1. **先上 Wappalyzer 插件** → 快速得到候选名单。
2. **再用 curl -I 查看响应头** → 寻找 Cookie 和特殊头。
3. **查看页面源码** → 静态资源路径、meta 标签、注释。
4. **触发错误页面** → 访问不存在的路径。
5. **尝试框架特有路径**（如 `/actuator/health`、`/admin/`）。
6. **如果还不确定** → 使用 WhatWeb 或在线指纹库验证。
