在网络安全分析中，区分一台远程主机是 **Linux** 还是 **Windows** 是信息收集的基础步骤。下面列出从 **最简单到最专业** 的判断方法。

---

## 一、最快最土的方法：看 TTL（Time To Live）
ICMP 包（如 `ping`）返回的 TTL 初始值在不同操作系统中不同，虽然中间路由会减1，但能提供有力线索。

| 操作系统         | 典型初始 TTL |
| ------------ | -------- |
| Windows      | 128      |
| Linux        | 64       |
| Unix/Solaris | 255      |

**示例**：
```bash
ping example.com
```
如果返回 `TTL=54` —— 接近 64，可能是 Linux（经过约10跳）；  
如果返回 `TTL=117` —— 接近 128，可能是 Windows。

⚠️ **注意**：TTL 可手动修改，且不同发行版/内核可能有差异（如有些 Linux 用 60 或 255），仅作参考。

---

## 二、看开放端口与服务指纹（最可靠）
使用 `nmap` 或 `masscan` 扫描常见端口，根据服务 Banner 准确识别。

### 2.1 典型必开端口差异
| 端口 | 服务 | Linux 典型 | Windows 典型 |
| --- | --- | --- | --- |
| 22/tcp | SSH | ✅ 几乎总是开放 | ❌ 默认关闭（除非装OpenSSH） |
| 3389/tcp | RDP | ❌ 很少开放 | ✅ 远程桌面，常见 |
| 445/tcp | SMB | ❌ 默认不开（Samba 可选） | ✅ 默认开启（文件共享） |
| 135/tcp, 139/tcp | NetBIOS/RPC | ❌ | ✅ Windows 特有 |


**快速扫描命令**：
```bash
nmap -p 22,135,139,445,3389 -O target.com
```
+ 开放 22 + 未开放 445 → 极可能是 Linux
+ 开放 3389 或 445 → 极可能是 Windows
+ 开放 135/139 → Windows

### 2.2 使用 `nmap -O` 进行操作系统猜测
```bash
nmap -O target.com
```
nmap 会基于 TCP/IP 栈指纹（窗口大小、选项顺序等）给出系统类型百分比。这比单纯看 TTL 准确得多。

---

## 三、看 HTTP 响应头（如果是 Web 服务器）
如果目标开放 80/443 端口，HTTP 响应头中的 `Server` 字段经常泄露信息。

```bash
curl -I http://target.com
```

| 常见 Server 值 | 倾向 |
| --- | --- |
| `nginx/1.18.0` | 可运行在 Linux 或 Windows，需结合其他特征 |
| `Apache/2.4.41 (Ubuntu)` | ✅ Linux (Ubuntu) |
| `Microsoft-IIS/10.0` | ✅ Windows Server |
| `Kestrel` | .NET Core，通常 Windows 但也可跨平台 |

另外： `X-Powered-By: PHP/7.4` 本身不区分 OS，但若同时看到 `ASP.NET` → Windows。

---

## 四、看默认页面与错误页面
+ **访问不存在的页面**：`http://target.com/this-file-not-exist-123456`
    - Linux + Apache/nginx → 通常返回 "404 Not Found" 页面，风格简洁，可能包含 "nginx/1.x.x" or "Apache"
    - Windows + IIS → 返回 "404 - File Not Found" 带深蓝色背景、微软风格
+ **访问** ****`favicon.ico`****：用 `curl -I` 或下载查看，有些默认图标会暴露 IIS。

---

## 五、利用网络协议特殊响应
### 5.1 SMB 协议探测 (端口 445)
使用 `smbclient` 或 `nmap` 脚本：
```bash
nmap --script smb-os-discovery -p 445 target.com
```

如果有 SMB 且返回 `Windows Server 2019` 之类 → Windows。

### 5.2 SSH 版本
```bash
nmap -sV -p 22 --script ssh-hostkey target.com
```

SSH 服务本身跨平台，但 Banner 里的软件版本可提供线索：  
`OpenSSH_for_Windows_8.1` → 明确 Windows；`OpenSSH_7.2p2 Ubuntu` → Linux。

## 六、大小写敏感性测试（很老的技巧，部分有效）
Windows 文件系统默认不区分大小写，Linux 区分。
**前提**：能访问 Web 服务器上的静态文件，例如 `/index.html`。
```bash
curl -I http://target.com/Index.html
curl -I http://target.com/index.html
```
+ 如果两个请求都返回 200 → 可能是 Windows/IIS（不区分大小写）
+ 如果只有 `index.html` 返回 200，`Index.html` 返回 404 → Linux 或大小写敏感的 Unix 系统
**但注意**：现代 Windows 上的 Apache 或 nginx 也可以配置大小写敏感，这个方法可靠性下降。
---
## 七、综合判断表（快速对照）
| 特征 | Linux / Unix | Windows |
| --- | --- | --- |
| 开放 22/SSH | 常见 | 少见（需额外安装） |
| 开放 3389/RDP | 极少 | 常见（Server版默认） |
| 开放 445/SMB | 极少（除非 Samba） | 常见（共享服务） |
| TTL 初始值 | 64 或 255 | 128 |
| 默认 Web Server | Apache, nginx | IIS (微软) |
| 大小写敏感 | 是 | 否（文件系统层面） |
| nmap -O 结果 | Linux, 2.6, 3.x, 4.x | Windows 10, 2016, 2019 |

---
## 八、实战流程
1. **最快**：`ping IP` 看 TTL
2. **次快**：`nmap -p 22,445,3389 IP` 看端口
3. **准确**：`nmap -O -sV IP` 做完整指纹
4. **Web 场景**：看 HTTP 响应头的 `Server` 和 404 页面风格
