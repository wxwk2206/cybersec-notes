# 3.后端语言
探测一个网站的后端编程语言（PHP、Python、Java、Go、ASP.NET 等），是渗透测试信息收集的重要一环。下面按 **可靠性从高到低** 列出判断方法。

---

## 一、HTTP 响应头直接泄露（最准最快）
用 `curl -I http://目标` 或浏览器开发者工具查看响应头。

| 响应头字段 | 可能的语言 | 示例值 |
| --- | --- | --- |
| `X-Powered-By` | PHP / ASP.NET / 其他 | `PHP/7.4.33`, `ASP.NET` |
| `Set-Cookie` | PHP → `PHPSESSID`   JSP → `JSESSIONID`   ASP.NET → `ASP.NET_SessionId`   Python (Django) → `sessionid`   Python (Flask) → 通常自定义，但也常见 `session` |  |
| `Server` 头 | 间接线索：   `Microsoft-IIS` → 常搭配 ASP.NET   `nginx` + `X-Powered-By: PHP` → PHP   `Apache` 可搭配 PHP/Python/Perl | `Server: nginx/1.18.0` |
| `X-AspNet-Version` | 明确是 ASP.NET | `X-AspNet-Version: 4.0.30319` |
| `X-AspNetMvc-Version` | ASP.NET MVC |  |
| `X-Generator` | 有时 CMS 会写 `Drupal` (PHP) 等 |  |
| `X-Drupal-Cache` | PHP (Drupal) |  |


**示例命令**：

```bash
curl -I https://example.com
```

---

## 二、根据文件扩展名（但现代路由常隐藏）
URL 中出现以下扩展名 → 基本确定后端语言：

| 扩展名 | 语言 |
| --- | --- |
| `.php` | PHP |
| `.asp` / `.aspx` | ASP / ASP.NET |
| `.jsp` / `.do` / `.action` | Java (JSP/Servlet/Struts/Spring MVC) |
| `.py` | Python（少见，除非源码泄露） |
| `.go` | Go（极少直接暴露） |

注意：很多网站使用无扩展名路由（RESTful），这个方法只能作为辅助。

---

## 三、根据默认错误页面风格
主动访问一个不存在的路径：`http://目标/this-file-not-exist-123456`
+ **PHP**：空白或提示 “No input file specified”，或典型的 PHP 错误（带黄色背景、路径泄露）。
+ **ASP.NET**：蓝色的 “Server Error in '/' Application” 页面，带堆栈跟踪（如果 customErrors=off）。
+ **Java (Tomcat/JBoss)** ：白色的 Apache Tomcat 404 页面，有时显示 “The requested resource is not available”。
+ **Nginx + 静态**：Nginx 默认 404 页面（简洁，带 Nginx 版本）。
+ **Python (Django)** ：Django 调试页面（DEBUG=True 时非常详细，显示 settings.py 路径等）。
+ **Flask**：简单文本 “Not Found” 或 HTML 页面。

---

## 四、根据特定语言/框架的默认路径或文件
尝试访问一些已知的默认路径，看响应内容或状态码：

| 语言/框架 | 默认路径或文件 |
| --- | --- |
| PHP | `/phpinfo.php` (若存在则直接暴露所有信息) |
| ASP.NET | `/WebResource.axd`, `/ScriptResource.axd` |
| Java (Tomcat) | `/manager/html`, `/docs/` |
| Java (Spring Boot) | `/actuator/health` (可暴露框架) |
| Python (Django) | `/admin/` (默认后台) |
| Python (Flask) | `/static/` 若自定义404，可结合特征 |
| Ruby on Rails | `/assets/application.js` 有时包含 Rails 版本 |
| Node.js (Express) | 默认 404 页面常是 `Cannot GET /xxx`（纯文本） |

---

## 五、根据 HTTP 方法的行为差异
不同后端对某些 HTTP 方法的处理可能存在特征。例如：
+ 发送 `OPTIONS *` 或 `OPTIONS /` 看返回的 `Allow` 头。ASP.NET 通常会报告 `GET,HEAD,OPTIONS,TRACE`，而 PHP 可能只报告 `GET,HEAD,POST`。
+ 发送畸形请求（如超大 Content-Length）看错误信息是否暴露语言栈。

此方法需要小心，避免触发 WAF 或破坏服务。建议仅在授权测试中尝试。

---

## 六、使用自动化工具（指纹识别）
| 工具 | 命令示例 | 特点 |
| --- | --- | --- |
| **WhatWeb** | `whatweb https://example.com` | 内置大量指纹，能识别 1800+ 种技术，包括后端语言、框架、CMS |
| **Wappalyzer** (浏览器插件) | 安装后直接访问网站 | 非入侵，实时识别 |
| **Retire.js** | 命令行扫描 JS 库 | 间接判断前端框架，但后端语言有时也能反映 |


---

## 七、结合其他信息综合推断
+ **操作系统**：Windows Server → 可能性高的是 ASP.NET 或 IIS 上的 PHP；Linux → PHP/Python/Java/Go/Ruby 等。
+ **中间件**：Apache + mod_php → PHP；Nginx + PHP-FPM → PHP；IIS + 无扩展路由 → ASP.NET；Tomcat → Java。
+ **CDN 或云服务商特征**：AWS 上常见 Node.js/Python/Java；Azure 常见 ASP.NET。
