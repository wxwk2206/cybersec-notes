# 4.cms识别
识别网站背后的CMS系统，是Web渗透测试和信息收集中至关重要的一环。不同CMS有独特的漏洞，摸清底细才能制定更有效的测试策略。这项技术对红蓝双方都有价值：红队用来寻找潜在突破口，蓝队则用它来检查自家系统是否有不该暴露的信息。

### 👀 手动识别：像侦探一样观察细节
手动识别是最直观、最常用的方法。你可以通过仔细查看网站的源代码和一些特征页面，来发现蛛丝马迹。

#### 📄 查看网页源代码
这是最基础的方法。在浏览器中按 `F12` 打开“开发者工具”，分析HTML源码。关键特征通常隐藏在`meta`标签、HTML标签、CSS/JS文件的路径和链接结构中。
+ WordPress：常出现`/wp-content/`、`/wp-includes/`等目录，`<meta name="generator" content="WordPress">`标签，以及`wp-`作为前缀的类名`<div class="wp-*">`。
+ Joomla：URL中含`index.php?option=com_`的特征，模板文件通常位于`/templates/`文件夹。
+ Drupal：有时会使用`drupal`作为CSS类名或ID名，HTML源码或注释中可能包含“Drupal”。
+ 国内常见CMS：如织梦（DedeCMS），会包含`/dede/`、`/templets/`等特有目录。

#### 🧩 检查HTTP响应头
响应头中的特定字段也能直接透露后端技术信息。
+ `Set-Cookie`：WordPress（`wordpress_`）、Joomla（`joomla_`）、国内CMS的长短不一或自定义格式。
+ `X-Powered-By`：泄露Web开发语言（`PHP/7.4`）或具体CMS。
+ 其他：`X-Drupal-Cache`（Drupal）、`X-Generator`（常见于国内CMS）。

#### 📁 探测特殊页面文件
几乎所有CMS都有一些在特定路径下的文件，访问它们也能获取重要信息。
+ `robots.txt`：许多CMS会在此文件指定规则，留下线索。例如，Discuz会在此文件中暴露`/data/`等目录，WordPress也会指引爬虫避开`/wp-admin/`目录。
+ 默认后台路径：尝试访问`/admin`、`/wp-admin`（WordPress）、`/dede`或`/manage`（DedeCMS）、`/administrator`（Joomla）等。如果这些路径能访问（即使只是登录页），就能直接确认CMS类型。
+ 特定文件：部分CMS存在独特文件，如WordPress的`/wp-content/readme.html`常包含版本信息；`/license.txt`也经常透露真实身份。
+ 版权信息：网站页面底部常见的`Powered by`等声明可能直接暴露CMS身份；不过为安全起见，许多站点会刻意删除。

### 🛠️ 自动化工具：用专业工具高效识别
对于批量任务或确认猜测，借助专业工具效率更高。自动化工具各有所长，可以组合使用。
+ **Wappalyzer**：最流行的浏览器插件，操作零门槛，在你访问网站时实时分析技术栈。
+ **WhatWeb**：Kali Linux自带的命令行工具，功能强大，支持自定义插件和批量扫描。
+ **CMSeek**：命令行的Python工具，支持超过**180种**CMS的检测，部分版本还可扫描账号等敏感信息。
+ **在线指纹库/集成工具**：如BugScaner、云悉 (Yunsee)、御剑等，无需安装，上传域名即可获得结果，有些还能检测CDN和WAF。

### 🎯 当标准方法失效：处理二次开发或小众CMS
当常用方法无效时，说明目标很可能经过了深度定制或使用了小众系统。此时需要更灵活的方法。
+ **利用哈希（Hash）值**：下载网站的`favicon.ico`图标或`logo.png`等文件，在本地计算其MD5哈希值，然后在公开的哈希库中查找匹配，从而识别出使用的CMS。
+ **分析页面结构和面包屑导航**：即便主题改变，但内容分类（`/article/`, `/product/`）和面包屑的逻辑结构往往沿用了原始系统的规则。
+ **检查默认资源目录和命名**：一些系统的目录命名（如`/public/`, `/static/`, `/assets/`）及其资源文件的命名逻辑（如`global.css`, `common.js`）会提供重要线索。
+ **深入分析网络请求**：通过“开发者工具”的“网络”（Network）标签关注XHR请求，其API路径设计（如`/api/get_article?id=123`）往往能揭示后端系统。
+ **借助GitHub进行代码搜索**：如果你发现一个非常独特的文件路径名、报错信息中的某句错误提示（**效果惊人**）、甚至一个奇特的CSS类名，尝试在GitHub搜索。这极有可能定位到其源码，从而**直接拿到CMS名称和版本**。
+ **检查源代码中的URL和路径**：
    - 查看源码中的“作者”或“generator”注释。
    - 分析JS/CSS文件的路径，寻找`/static/plugin/`这类CMS特有目录。
    - 进行目录扫描发现隐藏的`/backup/`, `/temp/`, `/cache/`等目录，倒推出CMS架构。

### 🚀 总结
CMS指纹识别贯穿整个渗透过程，是一个结合经验与工具的综合性技能。以下原则可以帮你少走弯路：
+ 先易后难：先从最快最直接的手动观察开始，再使用工具印证。
+ 多工具交叉验证：Wappalyzer识别模糊时，再用WhatWeb或CMSeek确认，尤其在针对WordPress这类系统时，获取精确小版本号很重要。
+ 注重收集指纹：维护自己的指纹库，把工作中遇到的CMS特征积累起来。
+ 尊重边界：你学到的追踪技巧同样能用来保护财产，在**获得明确书面授权前**，切勿在未授权目标上尝试。
