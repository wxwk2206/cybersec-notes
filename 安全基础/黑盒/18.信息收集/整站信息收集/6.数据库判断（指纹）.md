探测网站后端使用的数据库类型（MySQL、PostgreSQL、SQL Server、Oracle、MongoDB 等）是渗透测试信息收集的重要环节。下面按照**从被动到主动、从简单到深入**的顺序，给出判断方法。
## 一、通过错误信息直接泄露（最省力）
当应用存在 SQL 注入漏洞或参数异常时，可能触发数据库错误，错误信息中往往直接包含数据库类型和版本。

| 错误信息特征 | 数据库类型 |
| --- | --- |
| `You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax` | **MySQL** |
| `Unclosed quotation mark after the character string` 或 `Microsoft OLE DB Provider for ODBC Drivers` | **SQL Server** |
| `ORA-00933: SQL command not properly ended` | **Oracle** |
| `ERROR: syntax error at or near` 或 `pg_*` 相关函数 | **PostgreSQL** |
| `SQLite3::query()` 或 `SQLite database` | **SQLite** |

**如何主动触发**（仅在授权测试下）：
+ 在参数后加单引号 `'`、双引号 `"`、括号等特殊字符。
+ 访问 `?id=1` → 改为 `?id=1'`。
+ 观察页面是否返回数据库错误。
> 注意：现在很多生产环境关闭了详细错误提示，这个方法不一定有效。

---

## 二、通过 SQL 注入时的响应差异（有注入点时）
即使没有详细错误，不同数据库对某些 SQL 语句的处理也不一样，可以通过构造盲注语句区分。

| 判断手法   | MySQL                         | PostgreSQL           | SQL Server              | Oracle                                |
| ------ | ----------------------------- | -------------------- | ----------------------- | ------------------------------------- |
| 字符串连接  | `'a' 'b'` 或 `CONCAT('a','b')` | `'a'                 |                         | 'b'`                                  |
| 版本函数   | `VERSION()`                   | `VERSION()`          | `@@VERSION`             | `SELECT banner FROM v$version`        |
| 当前数据库名 | `DATABASE()`                  | `CURRENT_DATABASE()` | `DB_NAME()`             | `SELECT global_name FROM global_name` |
| 无表查询   | `SELECT 1`                    | `SELECT 1`           | `SELECT 1`              | `SELECT 1 FROM DUAL`                  |
| 注释风格   | `#` 或 `-- `                   | `-- `                | `-- `                   | `-- `                                 |
| 时间盲注函数 | `sleep(5)`                    | `pg_sleep(5)`        | `WAITFOR DELAY '0:0:5'` | `DBMS_LOCK.SLEEP(5)`                  |


**简单测试**（假设注入点在参数 `id`）：
+ `id=1 AND 1=1` 正常，`id=1 AND 1=2` 不正常 → 说明存在数字型注入。
+ 进一步尝试 `id=1 AND SLEEP(5)`，若延迟 → MySQL。
+ `id=1; WAITFOR DELAY '0:0:5' -- ` 若延迟 → SQL Server。

## 三、通过默认端口（辅助判断）
不同数据库常用默认端口，但端口不一定开放或可访问，且可能被修改，只能作为参考。

| 数据库 | 默认端口 |
| --- | --- |
| MySQL | 3306 |
| PostgreSQL | 5432 |
| Microsoft SQL Server | 1433 |
| Oracle | 1521 |
| MongoDB | 27017 |
| Redis | 6379 |
| Elasticsearch | 9200 |


**探测命令**（对授权目标）：
```bash
nmap -p 3306,5432,1433,1521,27017 target.com
```

如果端口开放且能识别 Banner，可直接确定数据库类型。

---

## 四、通过 HTTP 响应头或 JS 特征
某些 Web 框架或应用会在响应头或前端代码中暴露数据库信息。
+ `X-Powered-By: ASP.NET` → 后端常用 **SQL Server**。
+ `X-Powered-By: PHP/7.x` → 常搭配 **MySQL** 或 **MariaDB**。
+ `Server: Microsoft-IIS` → 常搭配 **SQL Server**。
+ 前端 JS 中出现 `mysql_`、`pg_`、`sqlsrv_` 等函数名（极少见，但可能因源码泄露）。

---

## 五、默认文件或路径（特定 CMS 或框架）
某些应用会使用特有的数据库配置文件路径，或者暴露数据库管理工具。
+ phpMyAdmin → 通常 `/phpmyadmin/`、`/pma/` → MySQL/MariaDB。
+ PHPPgAdmin → `/phppgadmin/` → PostgreSQL。
+ SQL Server Reporting Services → `/Reports/`。
+ Oracle EM → `/em/`。
如果这些路径可访问并需要弱口令，则直接明确数据库类型。

---

## 六、使用自动化工具
| 工具 | 功能 |
| --- | --- |
| **sqlmap** | 自动检测注入并识别后端数据库类型，加上 `--identify-waf` 参数 |
| **nmap** 脚本 | `nmap -p 3306 --script mysql-info target.com` 等 |
| **WhatWeb / Wappalyzer** | 部分能推断数据库（通过 Web 技术栈） |


**示例 sqlmap 用法**（仅授权测试）：
```bash
sqlmap -u "http://target.com?id=1" --dbms=mysql --banner
```

如果不确定，sqlmap 会自动探测。

---

## 七、综合判断流程
1. **先看 Web 技术栈**：IIS + ASP.NET → 很可能是 SQL Server；Linux + PHP → 很可能是 MySQL 或 PostgreSQL。
2. **尝试触发错误**：加单引号或乱码参数，看返回的错误信息。
3. **端口扫描**：扫描常见数据库端口，确认 Banner。
4. **若发现注入点**：使用数据库特有的函数测试（如 `SLEEP(5)`、`WAITFOR DELAY`）。
5. **自动化扫描**：用 sqlmap 辅助识别（确保授权）。
